# 510 SDD - Smoke Test, Record Rules, and Weekly Execution Plan

## 1. Background

本週工作重點是完成 prompt engineering pipeline 的 `10% smoke test`，並建立可重複使用的 experiment record 規則。

目前專案已經具備：

- `simple` prompt：single-stage baseline。
- `full` prompt：multi-stage prompt pipeline。
- local VLM generation：透過 Ollama local model。
- SaaS VLM baseline：目前主要使用 Gemini API。
- `smoke` / `formal` evaluation scope。

本週要解決的核心問題不是再大改 prompt，而是讓每次實驗可以被完整記錄、比較、重跑，並處理 Gemini API rate limit / quota 問題，確保本週可以交出 Gemini baseline result。

更重要的是，SaaS baseline 和 local inference 的最終目的不是各自產生 caption，而是要能計算 score，作為本專案最後階段的 local model evaluation。也就是：

```text
same image
-> SaaS VLM output as reference baseline
-> local VLM output as candidate
-> scoring
-> evaluate local model and prompt design
```

所以 record 不只要記錄 runtime / quota / parameter，也必須記錄 score、score 使用的 reference、score scope、score metric，以及 prompt comparison 結果。

## 5. Smoke Test Design

### 5.1 Scope

Smoke test 使用資料集的一部分，例如：

```text
smoke-percent = 10
```

目的不是取得正式 final score，而是快速檢查 scoring pipeline 是否可信：

- pipeline 能不能完整跑完。
- prompt output 是否符合 JSON schema。
- SaaS baseline 是否品質足夠。
- local model 是否能穩定輸出。
- local 和 SaaS 是否對同一張圖都有 output。
- score 是否可以被計算並正確寫入 record。
- `simple` 和 `full` 是否有可觀察差異。
- Gemini API 是否會遇到 quota / rate limit。

### 5.2 Required Generations and Score Comparison

Smoke test 需要產生四種 output：

- `local + simple`
- `local + full`
- `SaaS + simple`
- `SaaS + full`

這四種 output 的目的不同：

- local output 是 candidate，用來被評估。
- SaaS output 是 baseline/reference，用來評估 local。
- simple/full 是 prompt setting，不是任意交叉比對的 score axis。

正式 score comparison 只保留 same-mode local-vs-SaaS：

| Purpose | Candidate | Reference | Score? |
|---|---|---|---|
| simple prompt 下評估 local | local + simple | SaaS + simple | yes |
| full prompt 下評估 local | local + full | SaaS + full | yes |
| 檢查 prompt design | SaaS + simple | SaaS + full | manual / quality check |

這樣分開後：

- `local simple` vs `SaaS simple`
  - 評估 local model 在 simple prompt 下的表現。
- `local full` vs `SaaS full`
  - 評估 local model 在 full prompt 下的表現。
- `SaaS simple` vs `SaaS full`
  - 檢查 prompt design 是否讓 reference output 更完整。
  - 這部分由人工 review 和品質指標判斷，不當成 local model score。

不要計算：

- `local simple` vs `SaaS full`
- `local full` vs `local simple`

原因是這兩個 comparison 會混淆 prompt effect 和 model effect，不能回答本專案的核心問題。

### 5.3 Required Outputs

每次 smoke test 至少要輸出：

## 6. Experiment Record Rules

每次實驗都要記錄足夠完整的 metadata 和 score，否則結果不可比較。

Experiment record 至少分成兩種資料：

1. run metadata：
   - dataset。
   - model。
   - prompt mode。
   - hardware。
   - runtime。
   - API quota。
2. evaluation result：
   - reference provider。
   - candidate provider。
   - reference prompt mode。
   - candidate prompt mode。
   - score metrics。
   - valid output rate。
   - failure cases。

### 6.1 Basic Testing Info

必要欄位：

```json
{
  "run_id": "510_smoke_v1",
  "timestamp": "2026-05-10T00:00:00+08:00",
  "scope": "smoke",
  "smoke_percent": 10,
  "seed": 42,
  "dataset_root": "images",
  "excluded_dirs": ["MM-SkinQA"],
  "sample_count": 0,
  "category_counts": {}
}
```

### 6.2 Platform and Hardware

必要欄位：

```json
{
  "platform": {
    "machine": "local_mac | server | cloud",
    "os": "macOS | Linux",
    "hardware": "A10 | M-series | unknown",
    "gpu": "A10",
    "vram_gb": 0,
    "ram_gb": 0
  }
}
```

用途：

- local model speed 會強烈受 GPU / VRAM 影響。
- 同一個 prompt 在不同硬體上的 latency 不可直接比較。
- 之後畫圖時要能分辨是 prompt 慢，還是硬體慢。

```json
  "prompt_mode": "simple | full",

  "context_window": 0,
  "model_parameters": {
    "parameter_count": "unknown",

```

### 6.4 Runtime Metrics

必要欄位：

```json
{
  "metrics": {
    "total_duration_sec": 0,
    "load_duration_sec": 0,
    "prompt_eval_count": 0,
    "eval_count": 0,
    "tokens_per_second": 0,
    "input_tokens_avg": 0,
    "output_tokens_avg": 0,
    "success_count": 0,
    "failure_count": 0,
    "retry_count": 0
  }
}
```

其中：

- `total_duration_sec`：整次 model call 花多久。
- `load_duration_sec`：local model 載入時間。
- `prompt_eval_count`：input prompt token count。
- `eval_count`：generated output token count。
- `tokens_per_second`：生成速度。
- `request_count`：SaaS/API model call attempt 數量；`simple` 通常每張圖 1 次，`full` 通常每張圖 3 次。
- `api_success_count`：SaaS/API call 成功次數。
- `api_failure_count`：SaaS/API call 經過 retry 後仍失敗的次數。
- `success_count`：成功產生 output bundle/file 的 job 數量，不等於 API request 數。
- `failure_count`：產生 output bundle/file 失敗的 job 數量。
- `retry_count`：因 API limit 或 network issue 重試次數。
- `quota_consuming.request_count`：用來估算 RPM / RPD 壓力的 request 數，包含 retry 和被 block 的 call。
- `token_count.input`：Gemini `usageMetadata.promptTokenCount`，用來估算 TPM。
- `token_count.output`：Gemini `usageMetadata.candidatesTokenCount`。
- `token_count.total`：Gemini `usageMetadata.totalTokenCount`。

差異範例：

```text
1 image + Gemini full
-> caption call
-> VQA call
-> self-check call

request_count = 3              # API request / RPM pressure
quota_consuming.rpd_units = 3  # daily request quota pressure
token_count.input = 3813       # TPM pressure
api_success_count = 3          # API calls succeeded
success_count = 1              # one final full output file
```

也就是 `request_count` 看 API 消耗；`success_count` 看最後完成幾個 image/mode output。

### 6.6 Scoring Record

Scoring record 是本專案最後 evaluation 階段最重要的資料。

必要欄位：

```json
{
  "score_summary": {
    "scope": "smoke",
    "reference_provider": "gemini",
    "reference_model": "gemini-2.5-flash",
    "reference_mode": "full",
    "candidate_provider": "local",
    "candidate_model": "gemma4:e2b",
    "candidate_mode": "full",
    "sample_count": 0,
    "matched_image_count": 0,
    "unmatched_image_count": 0,
    "json_valid_rate": 0,
    "field_completion_rate": 0,
    "not_observed_usage_rate": 0,
    "bleu": 0,
    "rouge_l": 0,
    "meteor": 0,
    "cider_lite": 0,
    "overall_score": 0
  }
}
```

其中：

- `reference_provider`：標準答案來源，目前主要是 Gemini。
- `reference_mode`：必須和 candidate mode 對齊；例如 simple local 要對 `SaaS simple`，full local 要對 `SaaS full`。
- `candidate_provider`：被評估者，主要是 local model。
- `candidate_mode`：local 的 `simple` 或 `full`。
- `matched_image_count`：local 和 SaaS 都有 output 的 image 數量。
- `unmatched_image_count`：缺少任一邊 output，不能計入文字相似度 score。
- `json_valid_rate`：output 是否可以穩定被 parse。
- `field_completion_rate`：required fields 是否完整。
- `not_observed_usage_rate`：是否真的有使用 negative reporting。
- `bleu` / `rouge_l` / `meteor` / `cider_lite`：local candidate 對 SaaS reference 的文字相似度。
- `overall_score`：可選，用來做 summary ranking；如果公式還沒定，先記為 0 或 null。

每次 smoke test 必須記錄 comparison list，而不是把四種 output 任意交叉拿來算 score。

建議格式：

```json
    "local_simple_vs_saas_simple": {
      "type": "score",
      "purpose": "evaluate local model under the simple prompt baseline",
      "candidate": "local_simple",
      "reference": "saas_simple",
      "bleu": 0,

      "meteor": 0,
      "cider_lite": 0,
      "json_valid_rate": 0,
      "matched_image_count": 0
    },
    "local_full_vs_saas_full": {
      "type": "score",
      "purpose": "evaluate local model under the full prompt pipeline",
      "candidate": "local_full",
      "reference": "saas_full",
      "bleu": 0,
      "rouge_l": 0,
      "meteor": 0,
      "cider_lite": 0,
      "json_valid_rate": 0,
      "matched_image_count": 0
    },
    "saas_simple_vs_saas_full": {
      "type": "quality_check",
      "purpose": "validate whether full prompt improves SaaS baseline quality",
      "score_calculated": false,
      "manual_review_required": true,
      "json_valid_rate_simple": 0,
      "json_valid_rate_full": 0,
      "field_completion_rate_simple": 0,
      "field_completion_rate_full": 0,
      "not_observed_usage_rate_simple": 0,
      "not_observed_usage_rate_full": 0,
      "manual_review_result": "pass | fail | pending",
      "notes": ""
    },
    "local_prompt_effect_summary": {
      "type": "derived_metric",
      "purpose": "compare local full score against local simple score through their same-mode SaaS references",
      "bleu_delta": 0,
      "rouge_l_delta": 0,
      "meteor_delta": 0,
      "cider_lite_delta": 0,
      "interpretation": ""
    }
  }
}
```

解讀方式：

- `local_simple_vs_saas_simple`
  - 評估 local model 在 simple prompt 下的 baseline 能力。
  - 這是正式 score。
- `local_full_vs_saas_full`
  - 評估 local model 在 full prompt engineering 下的能力。
  - 這是正式 score。
- `saas_simple_vs_saas_full`
  - 檢查 prompt design 是否改善 SaaS baseline quality。
  - 這不是 local model score。
  - 主要由人工 review、schema valid rate、field completion、negative reporting 使用率判斷。
- `local_prompt_effect_summary`
  - 不直接比較 `local full` 和 `local simple` 的文字。
  - 只比較兩個正式 score 的差：
    - `local_full_vs_saas_full`
    - `local_simple_vs_saas_simple`
  - 用來回答 full prompt 是否讓 local model 在自己的 prompt setting 下更接近 SaaS baseline。

### 6.8 Baseline Quality Gate

SaaS baseline 必須先通過品質檢查，才能拿來當 scoring reference。

最低要求：

```json
{
  "baseline_quality_gate": {
    "reference_provider": "gemini",
    "reference_mode": "full",
    "json_valid_rate_min": 0.95,
    "field_completion_rate_min": 0.9,
    "manual_review_sample_count": 20,
    "manual_review_pass": false,
    "approved_for_scoring": false,
    "notes": ""
  }
}
```

如果 `approved_for_scoring` 是 false：

- 不能把 local score 當正式結果。
- 必須先修 prompt、修 Gemini calling strategy，或改 reference provider/model。

## 7. Gemini API Limit Problem

### 7.1 Observed Problem

上次發現 Gemini API exceed limit in a second。

可能原因：

1. 同時間 call 太密集。
2. `simple,full` 同時跑，導致每張圖多次 API call。
3. `full` prompt 本身需要多 stage，增加 request 數。
4. Gemini free/paid API tier 有 request-per-minute 或 token-per-minute 限制。
5. pipeline retry 太快，反而加重 rate limit。

### 7.2 Required Fix Direction

本週必須加入或確認：

- SaaS request delay。
- retry with exponential backoff。
- rate limit error logging。
- Gemini one-image probe：正式 Gemini smoke 前，random 選 1 張 smoke image，分別跑 simple/full 各一次。
- probe metadata record：記錄 request count、duration、retry、rate-limit/quota error、schema validity、prompt/output size。
- probe consumption prediction：根據 one-image result 預估整個 smoke subset 的 simple/full request 數、時間與 retry 風險。
- allow local-only dry run。
- allow SaaS smoke with very small percent first。
- allow `--modes simple` first, then `--modes full` separately。

### 7.3 Recommended Execution Order

先跑 local，確認 pipeline 和 prompt：

```bash
python -m pipeline generate \
  --run-dir runs/510_smoke_v1 \
  --local-scopes smoke \
  --saas-scopes none \
  --modes simple,full \
  --local-model gemma4:e2b \
  --workers 1
```

再跑 Gemini one-image probe，確認 API key / model / delay / retry 設定是否可用，並預估 simple/full Gemini smoke 消耗：

```bash
python -m pipeline gemini-probe \
  --run-dir runs/510_smoke_v1 \
  --scopes smoke \
  --seed 42 \
  --saas-model gemini-2.5-flash \
  --saas-request-delay-sec 2 \
  --saas-max-retries 5 \
  --saas-backoff-base-sec 3
```

probe 必須寫入：

```text

runs/510_smoke_v1/probes/<probe_id>/full.json
runs/510_smoke_v1/probes/<probe_id>/gemini_probe_record.json
```

如果 probe 失敗，先不要跑完整 Gemini smoke。應先調整：

- API key / model name。
- `--saas-request-delay-sec`。
- `--saas-max-retries`。
- `--saas-backoff-base-sec`。
- smoke sample size。

probe 通過後，再跑 Gemini simple：

```bash
python -m pipeline generate \
  --run-dir runs/510_smoke_v1 \

```

最後跑 Gemini full：

```bash
python -m pipeline generate \
  --run-dir runs/510_smoke_v1 \
  --local-scopes none \
  --saas-scopes smoke \
  --modes full \
  --saas-provider gemini \

  --workers 1 \
```

## 9. Text Data and RAG Plan

### 9.1 Problem

Textbook / ebook 通常內容很大，而且有很多 unrelated data。

如果直接整本餵給 model：

- 浪費 context window。
- 增加成本。
- 增加 hallucination risk。
- retrieval noise 會影響 prompt。

### 9.2 Required Approach

應該只抽 wound-related chapters / sections，例如：

- wound assessment。
- wound bed。
- wound edge。
- periwound skin。
- exudate。
- necrosis / eschar。
- burn depth visual cues。
- abrasion / laceration / puncture distinction。

### 9.3 Candidate Sources

目前候選：

- NCKU Library ebook。
- online wound-care resource。
- open textbook / guideline。
- dermatology visual description reference。

### 9.4 RAG Use Case

RAG 不應該直接告訴 VLM 圖中診斷。

## 13. Risk and Mitigation

| Risk | Impact | Mitigation |
|---|---|---|
| Gemini API rate limit | 無法產生 SaaS baseline | 先跑 one-image probe，降低 workers、加入 delay、分開 simple/full、先小比例 smoke |
| Full prompt 太慢 | local/SaaS 成本過高 | 先跑 simple，再跑 full；必要時做 compact full prompt |
| Record 不完整 | 結果不可比較 | 強制輸出 experiment record JSON |
| Score 沒有被記錄 | 無法完成 local model evaluation | experiment record 必須包含 score summary 和 evaluation comparison list |
| SaaS baseline 品質不穩 | local score 不可信 | scoring 前人工抽查 baseline |
| local/SaaS output image 不匹配 | BLEU/ROUGE 等 score 無效 | scoring 前計算 matched/unmatched image count |
| Textbook context 太大 | 浪費 context / 增加 noise | 只抽 wound-related section，未來用 RAG |
| 第三方 skill 被 commit | repo 變髒且不可控 | `.gitignore` ignore `.agents/` 和 `skills-lock.json` |
