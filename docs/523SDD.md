## 1. 背景

510 階段已經完成 10% smoke test 的核心 pipeline：

- local `simple` output：43 / 43。
- local `full` output：43 / 43。
- Gemini `simple` output：43 / 43。
- `local simple` vs `Gemini simple` same-mode scoring 已完成。
- `experiment_record.json`、`scores.json`、`scores.csv`、`scores.md`、charts 已產生。

目前最重要的狀態是：

```text
simple path 已經 end-to-end 完成
full path 目前只有 local full，沒有 SaaS full
```

本週不應該優先重跑 Gemini，因為：

- Gemini quota / RPD / RPM 有限制。
- `gemini-3.1-flash-lite` 雖然 quota 較高，但仍需小心 request pacing。

- SaaS full 成本較高，且 full prompt 每張圖約 3 次 API call，容易撞 RPM。

因此本週目標從「繼續大量生成」轉為「分析、整理、報告化、設計下一階段」。

## 5. Scoring Method Analysis Plan

### 5.1 Problem

目前 `local_simple_vs_saas_simple` 的文字相似度分數偏低：

```text
BLEU-4 = 0.046
ROUGE-L = 0.297
METEOR-lite = 0.380
CIDEr-lite = 0.211
```

但同時：

```text
schema_valid_rate = 1.0
field_completion_rate = 1.0
```

這表示 pipeline 格式穩定，但文字 similarity metric 不一定能完整反映 visual caption 品質。

### 5.2 Required Analysis

本週需要逐項分析：

- `caption_text()` 如何從 JSON 抽出比較文字。
- BLEU-4 對 wording / n-gram overlap 的敏感程度。
- ROUGE-L 是否比較能容忍句型差異。
- METEOR-lite 目前只是簡化 token overlap，不是正式 METEOR。
- CIDEr-lite 目前是簡化 n-gram cosine，不是正式 CIDEr。
- local 和 SaaS 是否描述同一視覺事實，但用不同詞彙。
- category-specific words 是否造成分數差異。
- negative reporting，例如 `not observed`，是否大量拉高或干擾 overlap。

### 5.3 Output

產出一份 scoring analysis section，至少包含：

```text
docs/523score_analysis.md 或併入 510progress.md / report
```

內容包含：

- 每個 metric 的公式或簡化版邏輯。
- 為什麼 BLEU 可能特別低。
- 代表性 image pair 的 local / SaaS caption 對照。
- local output 是否有 visual correctness 問題。
- metric 是否需要補充人工 review 或 rubric-based evaluation。

## 6. Metadata / Record Organization Plan

### 6.1 Required Metadata Table

將已經記錄的實驗資料整理成一張以 pipeline stage 為順序的 metadata table。欄位由左到右應反映實驗流程：

1. run id。
2. dataset split。
3. image count。
4. model type。
5. model。
6. model size / params。
7. prompt type。
8. platform。
9. GPU capacity / total VRAM。
10. runtime VRAM usage。
11. runtime GPU usage。
12. input token。
13. output token。
14. duration time。
15. prefill time。
16. decode time。
17. output format quality。
18. score 1-4。
19. 備註。

其中 `GPU capacity / total VRAM` 與 runtime usage 必須分開：

```text
GPU capacity / total VRAM = 硬體規格，例如 RTX 4090 / 24 GB
runtime VRAM usage = local model 實際執行時使用多少 VRAM
runtime GPU usage = local model 實際執行時 GPU utilization
```

SaaS model 的 runtime VRAM/GPU usage 不應填本機 GPU 數字，因為 Gemini 執行在 provider infrastructure；應標示 `not applicable`。

### 6.2 Current Limitation

目前 `pipeline.py` 只記錄硬體容量，不記錄 runtime GPU/VRAM usage。

目前已記錄：

```text
run_metadata.platform.gpu
run_metadata.platform.vram_gb
run_metadata.platform.gpu_detection_source
```

這些資料代表硬體參數，不代表模型執行時實際使用量。

目前未記錄：

```text
runtime_vram_used_gb
peak_vram_used_gb
runtime_gpu_utilization_percent
peak_gpu_utilization_percent
```

這些資料無法在實驗結束後可靠回推，必須在模型執行期間由 pipeline 取樣。

### 6.3 Future Pipeline Update Plan

後續要修改原始 `pipeline.py`，但本階段先只列入 plan，不在本次變更直接修改 pipeline code。

新增 runtime GPU monitor：

- 在 local model generation 開始前啟動取樣。
- 使用 `nvidia-smi` 讀取：
  - `memory.used`
  - `utilization.gpu`
- local simple / local full 每個 run mode 記錄：
  - average runtime VRAM usage。
  - peak runtime VRAM usage。
  - average runtime GPU usage。
  - peak runtime GPU usage。
- SaaS simple / SaaS full 不記本機 runtime GPU/VRAM usage，標示 `not applicable`。
- 將結果寫入：
  - 每張 output JSON 的 `metadata`，若能做到 per-image sampling。
  - `experiment_record.json` 的 `generation.local.by_mode.<mode>`，至少記錄 mode-level aggregate。

建議欄位：

```json
{
  "runtime_vram_used_gb_avg": 0.0,
  "runtime_vram_used_gb_peak": 0.0,
  "runtime_gpu_utilization_percent_avg": 0.0,
  "runtime_gpu_utilization_percent_peak": 0.0
}
```

### 6.4 Model Size Rule

模型參數量應使用官方文件或明確 model name，不應自行猜測。

- Gemma 4：依 Google Gemma docs，包含 E2B、E4B、31B、26B A4B；其中 26B A4B 是 MoE，generation 時每 token active 4B parameters，但完整 26B weights 仍需載入記憶體。
- Gemini：Google Gemini API docs 目前列出 model family / capabilities，但不公開 Gemini model parameter count，因此報告中標示 `not published / provider managed`。

## 7. PPT Material Plan

### 7.1 Purpose

PPT 不是展示所有 outputs，而是挑出代表性圖片說明：

- local 和 SaaS 都能穩定輸出 JSON。
- simple prompt 已經能完成 baseline evaluation。
- 文字 similarity 分數偏低，需要解釋 metric limitation。
- local simple / full 的差異可用來討論 prompt engineering 效果。

### 7.2 Suggested Slide Structure

1. 本週 pipeline status。
2. Dataset split / smoke sample。
3. 2x2 output matrix：local simple/full、SaaS simple/full。
4. Current completed path：local simple vs SaaS simple。
5. Score result table。
6. 為什麼 score 偏低：metric limitation。
7. Representative examples：圖片 + local output + SaaS output。
8. Gemini quota / block / rate-limit findings。
9. Next stage：domain knowledge + prompt-effect analysis。

### 7.3 Example Selection Criteria

挑圖時優先選：

- local / SaaS 都有 simple output。
- schema valid。
- local 和 SaaS 描述內容相似但用詞不同。
- score 低但人工看起來合理的 case。
- score 高且明顯對齊的 case。
- category 分布至少涵蓋 3-5 種 wound type。

## 9. Chinese Translation Plan

### 9.1 Motivation

目前 local / SaaS outputs 多為英文，人工 review 時閱讀成本較高。

本週可加入「繁體中文輔助翻譯」欄位，讓人工檢查更快。

### 9.2 Translation Rule

翻譯不能破壞專業詞彙。

建議格式：

```text
繁中翻譯（保留英文專業詞）
```

例：

```text
這是微調（fine-tune）的結果。
可見紅斑（erythema）與滲出液（exudate）。
```

### 9.3 Scope

本週先不要翻譯所有 43 筆。

建議先翻譯：

- PPT selected examples。
- score analysis selected examples。
- 3-5 張代表性圖片的 local / SaaS result。

### 9.4 Risks

- medical terms 翻譯不一致。
- 翻譯可能改變原意。
- 不應該用翻譯文本重新計算 English similarity score。

因此 translation 只作為 human review helper，不作為 scoring input。

### 10.2 Prompt-Engineering Analysis

目前本專案缺少直接相關研究，因此可參考其他領域的 prompt-engineering analysis，例如 code generation / Verilog generation paper。

可設計類似分析：

- prompt stage 是否提升 schema validity。
- prompt stage 是否提升 field completion。
- prompt stage 是否降低 hallucination。
- prompt stage 是否提升 evidence-backed category-specific reporting。
- simple vs full 是否在人工 rubric 中有差異。

### 10.3 Suggested Evaluation Beyond Text Similarity

未來可補：

- human review rubric。
- field-level agreement。
- visual feature coverage。
- hallucination count。
- safety compliance。
- category-specific evidence completeness。

這些可能比 BLEU 更適合 wound image-captioning。

## 12. Risks and Mitigation

| Risk | Impact | Mitigation |
|---|---|---|
| 過度解讀 BLEU 低分 | 錯誤判斷 local model 失敗 | 加入 metric limitation 和人工 example review |
| Gemini quota 浪費 | 無法完成後續 SaaS baseline | 本週不重跑，必要時只小批次 |
| SaaS full 缺失被誤解 | 誤以為 full prompt score 為 0 | 報告中標明 missing reference，不是模型表現 |
| 翻譯不精準 | 人工 review 誤判 | 保留英文專業詞並只作輔助 |
| chart 表達不清楚 | 報告誤導 | 修圖或加註解 |
| domain knowledge 太大 | context waste / noise | 只整理 wound-related concise notes |
