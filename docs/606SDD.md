目前專案已經有多個 smoke-test run，可用現有輸出重新計分，不需要重新呼叫 local model 或 Gemini：

- `runs/510_smoke_v1`
- `runs/523_smoke_v2`
- `runs/20260525_gemma4_e2b`
- `runs/20260525_gemma4_26b`
- standard SaaS simple baseline：`runs/saas_simple_baseline`

目前 scoring 已包含四個 lexical / surface-overlap 指標：

- `BLEU-4`
- `ROUGE-L`
- `METEOR-lite`
- `CIDEr-lite`

這些分數對 exact token、n-gram、文字順序很敏感。前一階段分析已發現，低分不一定代表模型看錯影像，可能只是 local output 與 SaaS baseline 使用不同措辭、同義詞、描述粒度或句型。因此本週應新增一個更偏語意相似度的 re-score 方法。

## 2. BERTScore Motivation

BERTScore 的目標是補足 BLEU / ROUGE 等 n-gram 指標的限制。

BERTScore paper 說明其做法是使用 contextual embeddings，比較 candidate token 與 reference token 的語意相似度，而不是只看 exact string match。該 paper 也指出 BERTScore 在 text generation evaluation 中，與 human judgment 有較好的相關性，並且對 paraphrase 更 robust。參考：

- Paper: <https://arxiv.org/abs/1904.09675>
- GitHub: <https://github.com/Tiiiger/bert_score>

本專案加入 BERTScore 的原因：

1. 傷口描述常出現同義詞：
   - `erythema` vs `redness`
   - `bulla` vs `blister`
   - `discoloration` vs `pigmentation`
   - `skin break` vs `open wound`
2. local 與 Gemini 可能描述同一個視覺事實，但句子結構不同。
3. lexical score 低時，需要一個 semantic score 協助判斷是否只是 wording mismatch。
4. 本週不重新生成 output，只需要對現有 outputs 重新計算分數，因此成本低、風險低。

## 5. Current Scoring Problem

目前四個 score 是 lexical score：

| Score | 主要依據 | 問題 |
|---|---|---|
| BLEU-4 | candidate n-gram precision | 對同義詞、改寫、句序非常敏感 |
| ROUGE-L | longest common subsequence | 仍依賴 exact token match |
| METEOR-lite | token overlap | 目前是簡化版，沒有 synonym/stemming |
| CIDEr-lite | n-gram count vector cosine | 沒有正式 CIDEr 的 TF-IDF corpus weighting |

已觀察到的問題：

- 文字分數偏低，但 schema / field completion 可以很高。
- local 描述可能較短，導致 recall 不足。
- local 與 Gemini 可能都合理，但使用不同詞。
- 某些圖片確實有 observation mismatch，不能只靠 semantic score 解決。

因此 BERTScore 的定位是：

```text
補充 lexical score，用 grouped semantic comparison 判斷不同文字來源之間的語意接近程度。
```

不是：

```text
判定影像醫學描述是否正確。
```

## 6. BERTScore Method Design

### 6.1 Comparison Target

本週只保留一個主要設計：`Grouped Semantic Comparison Score`。所有 comparison 都在同一份 grouped comparison report 中並列呈現。

目前流程有兩個 model-related stages：

```text
stage 1 = caption generation，產生英文 caption
stage 2 = translation，將 caption 翻成繁中，並保留必要英文專業詞
```

同時 reference 端也可能有翻譯，因此實際可比較的資料有四種：

| ID | Data | Meaning |
|---|---|---|
| `a` | reference English | SaaS / Gemini 原始英文 caption |
| `b` | translated reference | SaaS / Gemini caption 的繁中翻譯 |
| `c` | candidate English | local model 原始英文 caption |
| `d` | translated candidate | local model caption 的繁中翻譯 |

為了避免判讀混亂，不把所有比較混成單一 score，而是分成三組。這三組同等重要，只是回答不同問題：

| Group | Comparison | Name | Use |
|---|---|---|---|
| Caption quality | `a vs c` | `caption_source_score` | 檢查 local English caption 是否接近 SaaS English reference |
| Translation faithfulness | `a vs b` | `reference_translation_faithfulness` | 檢查 reference translation 是否保留 reference English 語意 |
| Translation faithfulness | `c vs d` | `candidate_translation_faithfulness` | 檢查 candidate translation 是否保留 candidate English 語意 |
| Human-review calibration | `a vs d` | `crosslingual_candidate_to_reference` | 觀察 translated candidate 與 English reference 的語意距離 |
| Human-review calibration | `b vs d` | `translated_review_score` | 對應人工主要閱讀的中文比較情境 |

簡化後的用途：

```text
1. a vs c：直接評估 captioning result。
2. a vs b、c vs d：評估 translation 是否改變原文語意。
3. a vs d、b vs d：校準人工看中文時，BERTScore 大概會如何反映我們的主觀感受。
```

這些 comparison group 都是本週 BERTScore 設計的一部分，沒有哪一組是附屬或次要。差別只在於用途不同：`a vs c` 回答 caption quality，`a vs b` / `c vs d` 回答 translation faithfulness，`a vs d` / `b vs d` 回答 human-review calibration。

Grouped comparison 需要同時回答：

- Caption generation 是否讓 local English caption 接近 SaaS English reference。
- Translation 是否保留各自英文 caption 的主要視覺語意。
- Cross-lingual comparison 是否能反映人工 review 時看到的中文 / mixed-language 結果。
- 不同 group 的分數差異是否能幫助定位問題：caption 本身、translation 本身，或人工閱讀語言造成的感受差異。

注意：

```text
不同 comparison group 必須分開輸出、分開命名、分開解讀，但 scoring criteria 需保持一致。
```

### 6.2 Text Extraction Rule

所有 comparison 必須使用與現有 lexical score 相同的 `caption_text()` 抽取規則，避免比較範圍不同造成誤判。

目前抽取欄位：

```text
caption.image_observation.visual_summary
caption.wound_features.shape_pattern
caption.wound_features.edges_margins
caption.wound_features.wound_bed
caption.wound_features.color
caption.wound_features.texture
caption.wound_features.fluid_exudate_bleeding
caption.wound_features.periwound_skin
caption.category_specific_check.observed_supporting_features
```

使用相同欄位的原因：

- 可與 `BLEU-4 / ROUGE-L / METEOR-lite / CIDEr-lite` 結果直接比較。
- 不混入 `metadata`、`schema_validation`、translation、runtime 等非描述內容。
- 不用繁中 translation text 取代英文 caption；英文、中文、mixed-language 來源必須各自保留。

Grouped comparison 使用相同欄位，但來源可能不同：

```text
a = reference English caption_text()
b = translated reference caption_text()
c = candidate English caption_text()
d = translated candidate caption_text()
```

因為 grouped comparison 同時包含 English、Chinese、mixed Chinese-English pairs，因此必須使用 multilingual embedding model，不能使用只適合英文的 model 設定。

另外，translation output 有時會同時包含繁中與英文專業詞，例如：

```text
紅斑（erythema）
滲出液（exudate）
表皮缺損（epidermal loss）
```

這是本專案刻意保留英文 medical term 的翻譯策略，不應被視為翻譯錯誤。BERTScore implementation 需要把這種 mixed Chinese-English text 當成正常輸入處理，並在 report 中記錄：

- translation text 可能是 mixed-language。
- 使用 multilingual embedding model 的原因之一，就是避免中英混合造成 embedding mismatch。
- mixed-language BERTScore 仍然只是 semantic consistency signal，不能單獨代表任一 comparison group 的完整品質。

### 6.3 BERTScore Output

BERTScore 應輸出三個主要數值：

| Metric | Meaning |
|---|---|
| `bertscore_precision` | candidate token 是否能被 reference 語意支持 |
| `bertscore_recall` | reference token 是否被 candidate 語意覆蓋 |
| `bertscore_f1` | precision / recall 的 harmonic mean |

在報告中主要看：

```text
bertscore_f1
```

但 precision / recall 必須保留，因為本專案常見問題是：

- candidate 寫得太短：recall 低。
- candidate 加入不在 reference 的內容：precision 低。

所有 comparison group 都使用同一套 BERTScore criteria：

| Comparison | Precision 解讀 | Recall 解讀 | F1 解讀 |
|---|---|---|---|
| `a vs c` | candidate English caption 是否被 reference English 支持 | reference English caption 是否被 candidate English 覆蓋 | local caption 與 SaaS reference 的語意接近度 |
| `a vs b` | translated reference 是否被 reference English 支持 | reference English 是否被 translated reference 覆蓋 | reference translation faithfulness |
| `c vs d` | translated candidate 是否被 candidate English 支持 | candidate English 是否被 translated candidate 覆蓋 | candidate translation faithfulness |
| `a vs d` | translated candidate 是否被 reference English 支持 | reference English 是否被 translated candidate 覆蓋 | cross-lingual candidate-to-reference calibration |
| `b vs d` | translated candidate 是否被 translated reference 支持 | translated reference 是否被 translated candidate 覆蓋 | human-review Chinese comparison calibration |

因此 BERTScore criteria 不是 translation-only。caption quality、translation faithfulness、human-review calibration 都共用 precision / recall / F1，且在 report 中應並列呈現。

### 6.4 Embedding Model

BERTScore 可以更換 embedding model。GitHub 文件中可以透過 CLI `--model` 或 Python API `model_type=` 指定 model，也可以設定 `num_layers`。BERTScore 官方範例包含 `roberta-large`，且建議報告 hash code 以利重現。

本專案必須在文件中明確列出可設定參數：

| Parameter | 用途 | 對 embedding / score 的影響 |
|---|---|---|
| `model_type` | 指定 embedding backbone | 決定使用哪個 encoder 產生 contextual embeddings |
| `num_layers` | 指定取第幾層 hidden states | 不同 layer 對語法/語意敏感度不同 |
| `lang` | 指定語言 | 影響預設 model 與 baseline rescale |
| `idf` | 是否啟用 token IDF weighting | 讓資訊量較高的 token 權重較大 |
| `rescale_with_baseline` | 是否用 baseline 校正分數 | 讓分數較容易解讀 |
| `batch_size` | 批次大小 | 影響速度與 GPU memory |
| `device` | `cuda` 或 `cpu` | 影響執行速度與資源使用 |
| `use_fast_tokenizer` | 是否使用 fast tokenizer | 影響 tokenizer 行為與速度 |

本週建議只使用 grouped / cross-lingual setting：

Grouped comparison 同時需要比較 English-English、English-Chinese、Chinese-Chinese、mixed Chinese-English text，因此要使用 multilingual embedding model。

建議候選：

```text
model_type = "bert-base-multilingual-cased"
```

或後續評估：

```text
model_type = multilingual sentence / XLM-R style encoder
```

Biomedical encoder 可列為後續研究，但本週不優先使用。原因是 grouped comparison 同時包含一般視覺詞、傷口詞彙、繁中、英文與 mixed-language text，單純 biomedical English encoder 不一定適合。

原則：

- Grouped comparison 不可使用英文-only `roberta-large` 作為預設設定。
- Grouped comparison 的設定必須記錄在 `grouped_bertscore_settings`。
- Grouped comparison 內不同 pair 的 BERTScore F1 必須依各自用途解讀，不可直接簡化成單一總分。
- Grouped comparison 必須允許繁中與英文專業詞共存；這是 translation format 的預期行為。
- 若 mixed-language output 比例很高，report 應標記 `mixed_language_expected = true`，避免把英文 term retention 誤判成翻譯不完整。

### 6.5 IDF Setting

BERTScore 支援 IDF weighting。IDF 的想法是讓常見詞權重較低、較少見且較有資訊量的詞權重較高。

本週建議：

```text
idf = False
```

原因：

- smoke set 只有 43 張圖，IDF corpus 太小，不穩定。
- 目前需要先得到穩定、可解釋的 semantic baseline。
- 未來若用 full dataset 或固定 corpus，可再啟用 IDF。

未來可測：

```text
idf = True
corpus = all candidate + reference caption_text from formal split
```

### 6.6 Baseline Rescale

建議：

```text
rescale_with_baseline = False
```

原因：

- Grouped comparison 使用 multilingual / cross-lingual setting，baseline rescale 是否適合需要先確認。
- 不同 comparison pair 語言組合不同，直接 rescale 可能讓分數更難解讀。
- 本週先保留 raw BERTScore 並完整記錄 hash code / settings。

注意：

- 若未來確認 multilingual baseline 可用，再測 `rescale_with_baseline = True`。
- 報告中必須保存 BERTScore hash code / settings。

### 9.3 Interpretation

若 BERTScore 高但 BLEU/CIDEr 低：

```text
可能是語意接近，但 wording / n-gram 不同。
```

若 BERTScore 低且 BLEU/CIDEr 也低：

```text
可能是真正內容差異、遺漏或描述錯誤。
```

若 BERTScore 高但人工看影像不合理：

```text
代表 BERTScore 只能判斷 text-to-text similarity，不能判斷 image correctness。
```

若 grouped comparison 中某一組 BERTScore 高：

```text
該 pair 的兩份文字在語意上接近，但仍要依 comparison group 解讀。
```

若 grouped comparison 中某一組 BERTScore 低：

```text
該 pair 可能有語意差異、資訊遺漏、翻譯改寫過度、或 multilingual embedding 設定不適合；需要人工抽查。
```

## 12. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| 第一次下載 embedding model 失敗 | 無法計算 BERTScore | 使用 local cache；文件中說明 dependency/model cache |
| GPU memory 不足 | 執行失敗或很慢 | batch size 降低；支援 `--device cpu` |
| BERTScore 分數偏高不易解讀 | 報告誤判 | 保留 lexical scores、完整 settings、人工抽查；rescale 只在 multilingual baseline 驗證後再開 |
| biomedical terms 對 default model 不友善 | semantic score 不夠準 | 後續測 biomedical model；人工抽查 |
| 誤把 BERTScore 當醫學正確率 | 結論錯誤 | 報告中標註 exploratory / text similarity only |
| 把不同 comparison group 混成單一分數 | 結論混亂 | caption quality、translation faithfulness、human-review calibration 分開輸出 |
| 使用英文-only model 評估 grouped comparison | cross-lingual / mixed-language score 不可信 | 使用 multilingual embedding model |
| 某一組 comparison score 高但另一組低 | 容易誤判模型或翻譯品質 | 並列呈現所有 group，搭配人工抽查 |

## 15. Future Plan: Direct Chinese Caption Generation

因為目前人工 review 主要閱讀中文，而現行流程是：

```text

```

所以 scoring logic 需要同時處理 caption quality、translation faithfulness、human-review calibration，判讀會比較複雜。

未來應測試：


|---|---|---|

| Direct Chinese caption | `outputs_zh/*/simple` | 測試模型是否能直接輸出可 review 的繁中 caption |

未來 comparison：

| Comparison | Meaning |

| English caption vs direct Chinese caption | direct Chinese generation 是否保留英文 caption 語意 |
| translated caption vs direct Chinese caption | 哪種中文輸出更符合人工 review 習慣 |
| SaaS direct Chinese vs local direct Chinese | 中文 captioning model comparison |

這個 future plan 不在本週實作範圍。本週先完成 BERTScore re-score，並用 grouped comparison 把現有四份資料整理清楚。

## 16. Final Note

本週目標不是增加更多 generation，而是讓現有結果能被更合理地解釋。

BERTScore 的角色是：

```text
semantic similarity supplement
```

不是：

```text
final clinical correctness metric
```

最終報告應同時呈現：

- lexical scores
- grouped semantic comparison BERTScore
- schema / field completion
- visual summary examples
- human review notes

這樣才能避免把單一分數誤解成模型品質的完整結論。
